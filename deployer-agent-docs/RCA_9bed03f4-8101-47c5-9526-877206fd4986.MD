This is **NOT a code bug and NOT a deploy failure.** The new feature code IS deployed and its startup migration ran correctly. ## Root cause
The application + `applied` state the user saw ("Application received", `member_status=='applied'`, a submission) is **in the preview environment / preview DB view, not in the deployed production DB**. This redeploy does not migrate preview data into the independent production database, so that record never reached production. Everything on the production side is internally consistent: no `applied` users, empty submissions, backfill correctly a no-op, Admin correctly shows "No submissions yet". The new code is live and, by inspection, wired correctly — it simply has not been run against any real `applied` data in production.
